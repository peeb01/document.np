threads Module (Pure Concurrency)

The threads module delivers native OS-level multi-core parallel execution. It provides hardware inspection (threads.num_cpu), asynchronous spawning (threads.run), future synchronization (task.wait()), and configurable race condition protection via Shared-Nothing isolated memory execution.

Hardware Core Inspection: threads.num_cpu

signature|fn threads.num_cpu() -> int

Inspect the host machine's hardware execution threads (logical CPU cores) to dimension thread pools dynamically:

Returns:intNumber of hardware CPU cores available on the current machine (minimum 1).
  • threads.num_cpu(): Function call syntax.
  • threads.num_cpu: Property access shorthand.
cpu_info.np
1import threads
2
3# Hardware inspection
4int cores = threads.num_cpu()
5print("Available CPU cores:", cores)
6
7# Property access shorthand
8print("Logical cores (property):", threads.num_cpu)
Expected Terminal Outputstdout
Available CPU cores: 8
Logical cores (property): 8

Level 1: Quickstart & Task Synchronization (task.wait)

signature|fn threads.run(func worker, ...args, bool isolated = false) -> Task

threads.run dispatches any function to execute on an asynchronous OS thread and returns a Task future handle:

Parameters
workerfunction

Target function identifier to execute asynchronously.

...argsany

Arguments passed to the worker function.

isolatedbool

Optional named flag (defaults to false). When true, arguments are deep-cloned to prevent race conditions.

Returns:TaskTask future handle. Call task.wait() or threads.wait(task) to block until completion and obtain the returned value.
  • task.wait(): Method syntax to wait and retrieve the result.
  • threads.wait(task): Functional module syntax.
  • threads(worker, ...): Shorthand callable syntax for threads.run.
level1_basic.np
1import threads
2import time
3
4func heavy_calculation(int a, int b) -> int:
5 time.sleep(0.05)
6 return a * b + 100
7
8func main():
9 print("Spawning asynchronous task...")
10
11 # 1. Spawn worker thread
12 task1 := threads.run(heavy_calculation, 20, 5)
13
14 # 2. Main thread can continue other operations concurrently
15 print("Main thread running concurrently...")
16
17 # 3. Block and retrieve computation result
18 result := task1.wait()
19 print("Task completed with result:", result)
20
21 # Alternative shorthand syntax:
22 task2 := threads(heavy_calculation, 50, 2)
23 print("Task 2 result:", threads.wait(task2))
24
25main()

Spawning asynchronous task...
Main thread running concurrently...
Task completed with result: 200
Task 2 result: 200

Level 3: Race Condition Prevention & Memory Model Trade-offs

Configurable memory safety: choose between raw C-speed pointer sharing or 100% race-condition-free isolated execution:

  • Shared Execution (isolated = false, Default): Pointer sharing with zero-copy overhead. Blazing fast native C-speed. Ideal for read-only datasets or when maximum throughput is critical. However, concurrent mutations to shared collections require careful design to avoid race conditions.
  • Isolated Execution (isolated = true): Shared-Nothing architecture. The NP runtime recursively deep-clones all arguments before spawning the thread. The worker receives an isolated replica in separate memory. Mutations made by the worker NEVER affect the caller, completely eliminating race conditions.
  • Overhead Trade-off: Deep-cloning massive datasets (e.g., 100 million items or high-resolution video frames) consumes memory allocations and CPU copying time. In languages like Dart, 'Transferable / Move semantics' transfer pointer ownership to avoid copies. In NP, the isolated flag gives you explicit control: use isolated=false for zero-copy read pipelines, and isolated=true when safe state isolation is mandatory.

1import threads

3func mutate_dataset(items) -> int:
4 items.append(9999)

Architectural Guideline

Default to isolated=false for read-heavy operations to achieve peak C-level memory speed. Enable isolated=true whenever passing mutable arrays or dictionaries that the worker will alter independently.

Level 4: Advanced Multi-Stage Concurrent Pipeline

Building a multi-stage high-throughput concurrent pipeline (Producer -> Worker Pool -> Aggregator):

level4_pipeline.np
1import threads
2import time
3
4# Stage 1: Batch Filter & Normalize Worker
5func filter_and_scale(batch, int multiplier) -> int:
6 int local_sum = 0
7 for val in batch:
8 if val > 10:
9 local_sum = local_sum + (val * multiplier)
10 return local_sum
11
12func main():
13 print("Starting Multi-Stage Parallel Pipeline...")
14
15 # Stage 0: Data partitioning
16 batch1 := [5, 12, 18, 7]
17 batch2 := [20, 8, 30, 4]
18 batch3 := [15, 25, 2, 9]
19
20 # Stage 1: Dispatched to worker pool with memory isolation
21 t1 := threads.run(filter_and_scale, batch1, 2, isolated = true)
22 t2 := threads.run(filter_and_scale, batch2, 2, isolated = true)
23 t3 := threads.run(filter_and_scale, batch3, 2, isolated = true)
24
25 # Stage 2: Aggregator collects results from futures
26 int res1 = t1.wait()
27 int res2 = t2.wait()
28 int res3 = t3.wait()
29
30 int grand_total = res1 + res2 + res3
31 print("Batch 1 Sum:", res1)
32 print("Batch 2 Sum:", res2)
33 print("Batch 3 Sum:", res3)
34 print("Pipeline Grand Total:", grand_total)
35
36main()
